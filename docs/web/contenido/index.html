01

Un vistazo

Un controlador es una clase corriente. Lo que devuelve decide el formato: un objeto se serializa a JSON, un String sale como texto plano, null es un 204. Sin anotación de por medio.

TareaController.javaJava
@Route("/api/tareas")
public class TareaController {

    @Inject Tareas tareas;

    @Get("/{id}")
    public Object ver(@Path("id") long id) {
        return tareas.findById(id);
    }

    @Post
    public Object crear(@Body @Valid Tarea tarea) {
        return Result.created(tareas.insert(tarea));
    }
}

Lux.run(8080, TareaController.class);

Si un campo no pasa la validación, la respuesta es un 422 con el mapa de campos y su motivo, sin que haya que escribirlo.

03

Principios

Cero dependencias
Solo el JDK. El driver JDBC de tu base de datos es la única excepción, y la pone la aplicación. Esta misma página se sirve con LuxCore y tampoco necesita nada.
Legible antes que ingenioso
Si una clase no se puede leer de corrido, se parte. Las 1041 líneas del despachador heredado se rehicieron como once clases con una responsabilidad cada una.
Medido, no proclamado
Toda afirmación de rendimiento sale del banco de pruebas. Los números que no se pudieron medir en condiciones no aparecen — ni siquiera con letra pequeña.
Honesto sobre lo que falta
La página de estado dice que no está listo para producción y enumera por qué. Prometer madurez que no existe es la forma más rápida de quemar el proyecto con el primer usuario.
04

De dónde viene

LuxCore nace de JxMVC 3.4.0, un framework MVC con cero dependencias que funciona y está en producción — pero que necesita Tomcat para arrancar. La comparación no es contra un rival cualquiera: es contra su propio antecesor.
