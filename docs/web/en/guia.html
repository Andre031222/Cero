01

Routes

@Route on the class sets the base; the verbs on the methods add the rest. One rule, no exceptions: an empty value maps to the base route.

AnnotationResulting routeNote
@Route("/api/tareas")/api/tareasClass base
@Get/api/tareasEmpty value = the base
@Get("/{id}")/api/tareas/{id}Route variable
@Get("/{id}/notas/{n}")…/{id}/notas/{n}Several variables
@Get("/archivos/*")/api/tareas/archivos/*Wildcard, only at the end
@Post @Put @Patch @Delete—Same criteria
  • Literal beats variable. /tareas/nueva resolves before /tareas/{id}, whatever order they are declared in.
  • Without @Route, the base comes from the class name: ReporteController → /reporte.
  • Duplicate routes fail at startup, not on the first request.
  • 405 with Allow. If the route exists but the verb does not, the response lists the valid verbs.
  • HEAD resolves against GET automatically, with no body.

Loose routes, with no controller

LambdasJava
.routes(r -> r
    .get("/salud", ctx -> "ok")
    .get("/version", ctx -> Map.of("version", "0.3.0"))
    .post("/eco", ctx -> ctx.bodyText()))

Injection

Mark a service with @Service and it is built the first time somebody asks for it. Controllers receive it with @Inject, by field or by constructor.

ServicesJava
@Service
public class Catalogo {
    @Inject Repositorio repositorio;      // by field
}

@Service
public class Facturas {
    private final Catalogo catalogo;
    @Inject Facturas(Catalogo catalogo) {   // by constructor
        this.catalogo = catalogo;
    }
}

// or by hand, handy for swapping in tests
Lux.app().service(Reloj.class, () -> Instant.now())
  • Services are singletons: one instance per application.
  • They are also registered under their interfaces, so you can ask for the contract.
  • Circular dependencies are detected and the error names the whole chain.

The annotations go on the components of a record or the fields of a class. @Valid next to @Body validates before entering the method.

AnnotationWhat it checksDefault message
@RequiredNot null, not empty, not blankes obligatorio

@Range(min, max)Numeric rangedebe estar entre N y M
@EmailEmail formatno es un correo válido

Tarea.javaJava
public record Tarea(
        @Id long id,
        @Required @Length(min = 3, max = 120) String titulo,
        @OneOf({"baja", "media", "alta"}) String prioridad) {}

// a rule of your own
public class Ruc implements Rule<String> {
    public boolean test(String v) { return v.length() == 11 && v.startsWith("20"); }
    public String message()    { return "no es un RUC válido"; }
}

06

Errors

Throw HttpException with whatever status you want, or register a handler with @OnError for an exception from your own domain.

Error handlingJava
@Get("/{id}")
public Object ver(@Path("id") long id) {
    Tarea t = tareas.findById(id);
    if (t == null) throw new HttpException(404, "no existe la tarea " + id);
    return t;
}

@OnError(SaldoInsuficiente.class)
public Object saldo(SaldoInsuficiente fallo) {
    return Result.json(Map.of("motivo", fallo.getMessage())).status(422);
}
Uncaught exceptions never leak details

Any exception that is not an HttpException returns a 500 with the generic message "error interno". The stack trace goes to the ErrorReporter, not to the response.

07

Optional base class

A LuxCore controller inherits from nothing: it is an ordinary class with annotations, and the Context arrives as a parameter when it is needed. If a controller uses it in nearly every method, you can extend Controller and save yourself the trouble.

With the base classJava
@Route("/panel")
public class PanelController extends Controller {

    @Get("/perfil")
    public Result perfil() {
        if (!autenticado()) return redirect("/auth/login");
        return view("perfil", Map.of("usuario", usuario().name()));
    }

    @Get("/informe/{id}")
    public Result informe() {
        var informe = informes.porId(param("id"));
        if (informe == null) throw fallo(404, "no existe");
        return json(informe);
    }
}

It brings param, query, form, header, cookie, body, session, usuario, autenticado, and on the response side view, json, text, html, redirect, created, noContent, status and fallo. For everything else, ctx() returns the whole Context.

It really is optional. Both styles live side by side in the same application: whoever does not extend it keeps receiving the Context as a parameter and never learns this exists.

Why it does not keep the request in a field

There is a single instance of the controller, shared by every request, and LuxCore serves each connection on its own virtual thread. A field holding the request would be a race: two simultaneous requests would overwrite it and one would end up answering with the other's data. That is why the helpers read from a per-thread holder. There is a test that fires 200 simultaneous requests and checks that each response carries its own data; with a shared field, it fails.

08

Sessions and access

The session is requested from the context. It is born the first time it is used, and the cookie goes out HttpOnly, SameSite=Lax and Secure if the request came over HTTPS.

SessionJava
Session sesion = ctx.session();
sesion.set("usuario", correo);
String quien = sesion.get("usuario", String.class);
sesion.invalidate();                     // on sign-out
Rotate the identifier when signing in

The identifier a visitor holds before signing in cannot stay valid afterwards: whoever had planted it in their browser would end up with an authenticated session. That is session fixation, and one line avoids it: 

if (Passwords.matches(clave, usuario.hash())) {
    ctx.session().regenerateId();        // ← right here, before storing anything
    ctx.session().set("usuario", usuario.correo());
}

It preserves the contents —including the CSRF token— unlike invalidate(), which wipes everything.

Passwords are stored with Passwords: PBKDF2-HMAC-SHA256 at 210,000 iterations, a per-password salt and constant-time comparison. The format carries the cost inside, so it can be raised without invalidating what is already stored.

PasswordsJava
String guardado = Passwords.hash(clave);
boolean vale = Passwords.matches(clave, guardado);
if (Passwords.needsRehash(guardado)) {   // the cost went up since it was stored
    usuarios.actualizarHash(id, Passwords.hash(clave));
}

And to sign in with Google, Microsoft or GitHub, OAuth brings the complete flow with PKCE and signature verification of the id_token.

OAuth 2.0Java
OAuth google = OAuth.google(id, secreto, "https://mi-sitio/auth/google/vuelta");

@Get("/auth/google")
public Result entrar(Context ctx) {
    var salida = google.comenzar();
    ctx.session().set("oauth.estado", salida.estado());
    return Result.redirectExternal(salida.url());
}

@Get("/auth/google/vuelta")
public Result vuelta(Context ctx) {
    var identidad = google.completar(ctx.query("code"), ctx.query("state"),
                                     ctx.session().get("oauth.estado", String.class));
    ctx.session().regenerateId();
    ctx.session().set("usuario", identidad.correo());
    return Result.redirect("/panel");
}

For several instances, or so that sessions survive a deployment, the store goes into a table. With the in-memory one —the default— every deployment throws everybody out.

Shared sessionsJava
ServerOptions.builder()
    .sessionStore(JdbcSessions.of("lux_sesiones").createTable())
    .sessionMaxLifetime(Duration.ofHours(12))   // a lifetime cap, not just inactivity
    .build();

Tasks and cache

Work outside the request: fire and forget, wait for a result, repeat every so often or follow a cron expression. Each task runs on its own virtual thread, so blocking inside one does not cost a platform thread.

TasksJava
Tasks tareas = Tasks.start();

tareas.run(() -> correo.enviar(aviso));                  // and forget about it
var futuro = tareas.submit(() -> informe.generar());       // with a result
tareas.every(Duration.ofMinutes(5), () -> sondear());
tareas.cron("0 3 * * *", () -> respaldo());                // at three in the morning

And for whatever is expensive to compute and changes little, a cache with per-entry expiry:

Cache and EventsJava
Cache<String, List<Noticia>> portada = Cache.of(Duration.ofMinutes(10));
List<Noticia> ultimas = portada.get("portada", clave -> noticias.ultimas(6));

// Event bus: whoever publishes does not know who is listening.
eventos.publish(new NoticiaPublicada(id));

@Listens
public void alPublicar(NoticiaPublicada evento) {
    portada.invalidate("portada");
}

Metrics and OpenAPI

Metrics counts requests and times per route, with percentiles, and knows how to write itself in the format Prometheus reads.

ObservabilityJava
Metrics metricas = Metrics.enabled().ignore("/estaticos");

Lux.app()
   .service(metricas)
   .use(metricas)
   .use(AccessLog.combined())
   .routes(r -> r.get("/lux/metrics", metricas.endpoint()))
   .start();

OpenApi describes the registered routes —parameters, types, what requires authentication— with nothing extra to annotate. It is useful for generating the frontend's TypeScript client from the server instead of writing it twice.

OpenAPIJava
.routes(r -> r.get("/openapi.json", ctx -> OpenApi.of("Mi API", "1.0").json()))

Behind a proxy

LuxCore speaks HTTP/1.1. For HTTP/2, HTTP/3 and automatic certificates you put nginx or Caddy in front, which also absorbs slow connections. It is the recommended way to deploy it.

Two things you have to declare

Behind a proxy, the request arrives from the proxy itself and in plain text. If nobody tells it otherwise, the application believes nobody is using HTTPS —and does not mark the session cookie as Secure— and sees everyone coming from the same address, so the rate limiter counts them all together and the first to hit the cap blocks the whole site. 

ServerOptions.builder()
    .behindProxy(true)                  // honours X-Forwarded-Proto
    .trustProxy("127.0.0.1", "::1")       // and X-Forwarded-For, only from there
    .build();

The trust list is neither optional nor cosmetic: believing those headers wherever they come from lets anyone claim to be another address, and with that they slip past the limiter and pollute the logs.

And static files with their cache directive, because otherwise the browser revalidates more than it needs to:

Static filesJava
StaticFiles.from(raiz, "/medios")
    .cacheControl("public, max-age=3600");

// For assets with a fingerprint in the name — estilo.a1b2c3.css — you can go all in:
StaticFiles.fromClasspath("estaticos")
    .cacheControl("public, max-age=31536000, immutable");

With React, Svelte or Vue

LuxCore does not force you to use its template engine. It can serve JSON and nothing else and let the frontend paint it, which is the normal thing today. Both ways live side by side in the same application: some routes return views and others JSON.

In development · two servers

The frontend on its own server —5173 for Vite, 3000 for Next— and LuxCore on its own. Since they are different origins, you have to open CORS for that port and only for that one:

DevelopmentJava
Lux.app()
   .use(Cors.allowing("http://localhost:5173"))
   .controllers(ApiController.class)
   .start();

In production · a single artefact

You build the frontend, copy its output into the resources, and out comes one jar that serves both. No nginx in front to join them, no two deployments.

One jar with everythingJava
Lux.app()
   .controllers(ApiController.class)          // /api/... returns JSON
   .fallback(StaticFiles.fromClasspath("front").spa()
                        .cacheControl("public, max-age=31536000, immutable"))
   .start();
What spa() does and why it is needed

An application that routes on the client —React Router, Svelte's router— does not have one file per route: only index.html exists. Without spa(), going straight to /panel/usuarios/7 would give a 404 and the application would only work when navigating from the home page.

With spa(), a route that does not exist as a file returns index.html and the browser decides what to paint. But only for page routes: a missing .css or .png still gives a 404 — handing them the home page's HTML turns an obvious error into one that takes an hour to find.

If your frontend generates one file per route —Next.js static export, Astro, Hugo— you do not need spa(): /nosotros finds nosotros/index.html on its own.

How the project ends up

StructureText
mi-proyecto/
├── backend/            # LuxCore — Maven, Java 21
│   ├── pom.xml
│   └── src/main/
│       ├── java/...
│       └── resources/front/     # ← the built frontend is copied here
└── frontend/           # React, Svelte, Vue, whatever
    ├── package.json
    └── src/...

Copying the frontend output into resources/front/ is done by your build script or by maven-resources-plugin. From there, mvn package and you have a jar with everything inside.

13

Real time

Two ways, and nearly always you want the first.

Server-sent events · one direction

The server sends when there is something, instead of the browser asking every two seconds. It is ordinary HTTP: it crosses proxies with nothing to configure and the browser reconnects on its own. For a dashboard, a progress bar or a notification, it is exactly what is needed.

ServerJava
@Get("/eventos")
public void eventos(Context ctx) throws InterruptedException {
    try (Sse eventos = Sse.open(ctx.response())) {
        while (eventos.abierto()) {
            eventos.send(Json.write(metricas.snapshot()));
            Thread.sleep(1000);
        }
    }
}
BrowserJavaScript
const eventos = new EventSource('/eventos');
eventos.onmessage = e => pintar(JSON.parse(e.data));
Why that loop is not a problem

That while keeps the thread inside for as long as the dashboard is open. With platform threads it would be unworkable —a hundred dashboards, a hundred blocked threads— but LuxCore serves each connection on its own virtual thread: a hundred dashboards are a hundred virtual threads, costing a few hundred bytes each. That is why here you can write blocking code without paying for it.

This site's dashboard uses it: the numbers you see are pushed by the server every second.

WebSocket · both directions

For when the browser also has to talk — a chat, a shared editor, a game. It costs a separate protocol and a configured proxy; if you only need to receive, do not use it.

WebSocketJava
.routes(r -> r.ws("/chat", socket -> {
    socket.onMessage(texto -> socket.send("eco: " + texto));
    socket.onClose(() -> log.info("se fue"));
}))
On "reactive programming"

LuxCore has no Flux, Mono or anything of the sort, and that is a decision. That style exists to avoid blocking platform threads, which are expensive. With Java 21's virtual threads they stop being expensive: you can write ordinary top-to-bottom code that blocks — and the performance is the same, without the cost of chaining operators or debugging unreadable stack traces. Same capability, another road.
