None of them drags in external dependencies. The only foreign JAR you will see in your application is your database's JDBC driver, and you put that there yourself.

02

Maven

After ./lux install, the artefacts sit in your local repository and are declared like any other.

pom.xmlXML
<!-- the minimum for an API: pulls in lux-http -->
<dependency>
    <groupId>lux</groupId>
    <artifactId>lux-core</artifactId>
    <version>0.3.0</version>
</dependency>

<!-- if you serve HTML -->
<dependency>
    <groupId>lux</groupId>
    <artifactId>lux-view</artifactId>
    <version>0.3.0</version>
</dependency>

<!-- if you talk to a database -->
<dependency>
    <groupId>lux</groupId>
    <artifactId>lux-data</artifactId>
    <version>0.3.0</version>
</dependency>

<!-- the driver is yours to add: this is the only external one -->
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <version>42.7.4</version>
</dependency>
03

What to take

HTTP only
lux-http · 88 KB
A server with hand-written handlers, no routing and no injection. For a webhook, a health check or a small proxy.
A JSON API
lux-core · 235 KB
Routes, injection, validation, security and metrics. The usual choice for a service.
A site with HTML
+ lux-view · 273 KB
Adds templates with inheritance and escaping by default.
With a database
+ lux-data · 308 KB
JDBC, pool, transactions, repositories and table-backed sessions. Plus your engine's driver.
Migrating from Tomcat
+ lux-adapter-servlet · 321 KB
Deploys the same application inside Tomcat while you make the switch, and lets you go back if you need to.
04

From source

Build and installShell
git clone git@github.com:Andre031222/LuxCore.git
cd LuxCore

./lux install     # builds, tests and installs into ~/.m2
./lux package     # the JARs only, with their sizes
./lux test        # all 1,342 tests
./lux run         # the example application on :8080
./lux new mi-app  # a new project, ready to run
./lux docs        # this documentation, served by LuxCore
./lux cache       # what it takes up, and --purge to empty it
./lux clean       # removes what was generated

The example application lives in java/ejemplo: a complete task manager with views, forms, a database and a REST API, plus 36 end-to-end tests. It is the best place to start reading.

Checking what you built

FingerprintsShell
shasum -a 256 java/lux-core/target/lux-core-0.3.0.jar

# should start with 5309738f66a6fbde
05

Requirements

WhatVersionWhy
JDK21 or newer Virtual threads: the server assigns one per connection, and without them the model does not hold up. Developed and measured with OpenJDK 25.
Maven3.9+ Only to build. Not needed at runtime.
Systemany No native code and no system paths. Tested on macOS and Linux; not verified on Windows.
JDBC driveryour engine's Only if you use lux-data. Verified with PostgreSQL 16, MySQL 8 and H2.
Tomcat10.1+ Only if you deploy with lux-adapter-servlet. Not used in normal mode.
