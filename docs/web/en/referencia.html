01

Databases

lux-data speaks JDBC and nothing else. Any engine with a JDBC driver works — the driver comes from your application, which is the only external dependency LuxCore allows.

EngineStatusNote
H2 2.2VerifiedIn memory and on file. The engine behind the example application and its 36 end-to-end tests.
PostgreSQL 16Verified47 cases in a container: BIGSERIAL, exact decimals, native booleans, dates and LIMIT/OFFSET.
MySQL 8VerifiedThe same 47 cases: AUTO_INCREMENT, booleans over TINYINT and generated keys.
MariaDBNot verifiedShares protocol and dialect with MySQL, so it should behave the same.
SQL ServerNeeds workDoes not support LIMIT/OFFSET: it uses OFFSET … FETCH. Pagination needs an adjustment.
OracleNot verifiedReturns column names in upper case, which is already handled since that bug was fixed.
SQLiteNot verifiedNo write concurrency: the pool should be set to 1.
What "verified" means here

The three engines marked as such pass the same suite of 47 cases, running in containers: generated keys, exact decimals, booleans, dates, pagination, upper-case aliases, committed and rolled-back transactions, repositories and batch inserts. That suite found a real bug —Row.as() ignored @Column and returned null fields— that no test with a mocked driver had caught.

02

Where it runs

There is no native code and nothing platform-specific. Wherever there is a JDK 21 or newer, it runs the same.

SystemStatusNote
macOSTestedIntel and Apple Silicon. Where it was developed and where the 1,342 tests run.
LinuxTestedAll 1,342 tests green on Linux 6.12, with real PostgreSQL and MySQL. In continuous integration, on JDK 21 and 25, on every change.
WindowsNot verifiedNothing touches system-specific paths or permissions.
ContainersNot verifiedAny image with a JRE 21. With no servlet container, the image is the JRE plus 223 KB.
The real requirement
Java 21, because of virtual threads: the server assigns one per connection, and without them the model does not hold up. Developed and measured with OpenJDK 25.
No native code
No JNI, no system libraries, no absolute paths. The JAR is the same everywhere.

What this table says, and what it does not

It says LuxCore wins on everything except image size, and there it loses by 0.2 MB. It boots 4.3 times faster than the next one, uses the least memory of the six and leads on all three endpoints. On /db —the one that measures the framework doing real work— it beats the JxMVC it came from by 38 %.

What it does not give you is quotable absolute figures: this was measured on Docker Desktop, inside a VM. The conditions were identical for all six, so the comparison is fair; the individual numbers need repeating on bare metal before they go anywhere.
