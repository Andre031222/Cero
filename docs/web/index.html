01

Cómo se ve

Un controlador es una clase corriente. Lo que devuelve decide el formato: un objeto se serializa a JSON, un String sale como texto plano, null es un 204. Sin anotación de por medio.

ApiController.java Java 
@Route("/api/tareas")
public class ApiController {

    @Inject Tareas tareas;

    @Get("/{id}")
    public Object ver(@Path("id") long id) {
        return tareas.findById(id);
    }

    @Post
    public Object crear(@Body @Valid Tarea tarea) {
        return Result.created(tareas.insert(tarea));
    }
}
Arrancarlo Java 
Lux.run(8080, ApiController.class);

// o con todo declarado
Lux.app()
   .port(8080)
   .views(Templates.fromClasspath("plantillas"))
   .use(Csrf.enabled())
   .use(RateLimit.perMinute(300))
   .controllers(ApiController.class)
   .start();

Si un campo no pasa la validación, la respuesta es un 422 con el mapa de campos y su motivo, sin que haya que escribirlo.

03

Bases de datos

lux-data habla JDBC y nada más. Sirve cualquier motor con driver JDBC — el driver lo pone tu aplicación, que es la única dependencia externa que LuxCore admite.

Probado
H2 2.2, en memoria y en archivo. Es el motor de la aplicación de ejemplo y de sus 36 pruebas de punta a punta.
Debería andar
PostgreSQL, MySQL, MariaDB, SQL Server, Oracle, SQLite. Nada del código es específico de un motor: sentencias preparadas, LIMIT/OFFSET y claves generadas por JDBC.
Sin verificar
Ninguno salvo H2. Los tipos, las zonas horarias y la paginación cambian entre motores; hasta que no se corra contra PostgreSQL y MySQL reales, «debería andar» es una hipótesis.
Mayúsculas
Los nombres de columna se buscan sin distinguir mayúsculas. H2 y Oracle devuelven TITULO, PostgreSQL titulo: los dos funcionan igual.
Inyección SQL
Los valores nunca se concatenan. Los nombres de tabla y columna se validan carácter a carácter antes de tocar la base de datos.
04

Dónde corre

No hay código nativo ni nada específico de una plataforma. Donde haya un JDK 21 o superior, corre igual.

Linux
Cualquier distribución con JDK 21+. Es el destino previsto para producción.
macOS
Intel y Apple Silicon. Es donde se desarrolló y donde corren las 642 pruebas.
Windows
Nada del código toca rutas ni permisos específicos del sistema, pero no se ha ejecutado allí todavía.
Contenedores
Cualquier imagen con JRE 21. Sin contenedor de servlets, la imagen es el JRE más 223 KB.
Requisito real
Java 21 por los hilos virtuales: el servidor asigna uno por conexión, y sin ellos el modelo no se sostiene.
05

Instalación

LuxCore no está publicado en Maven Central y su repositorio es privado por ahora. Hoy se instala compilándolo, que deja los artefactos en tu repositorio local de Maven.

Compilar e instalar Shell 
git clone git@github.com:Andre031222/45.Soft_LuxCore.git
cd 45.Soft_LuxCore/java
mvn install
pom.xml XML 
<!-- toma solo los módulos que uses -->
<dependency>
    <groupId>lux</groupId>
    <artifactId>lux-core</artifactId>
    <version>0.1.0</version>
</dependency>

La aplicación de ejemplo está en java/ejemplo. Levanta un gestor de tareas completo —vistas, formularios, base de datos y API REST— con java -cp … ejemplo.App.

06

Estado

No usar en producción todavía

El servidor HTTP tiene días de vida. Una auditoría encontró una inyección CRLF a las pocas horas de escribirlo, y construir la primera aplicación real destapó otros cuatro fallos. Todos están corregidos y cubiertos por pruebas — el punto es que aparecieron, y que ese proceso no ha terminado.

  • ✓
    642 pruebas en verde, cero dependencias verificadas
  • ✓
    Una aplicación completa corriendo de punta a punta
  • ✓
    Endurecimiento explícito: request smuggling, path traversal, inyección de cabeceras, CSRF
  • ✗
    Sin fuzzing del parser ni banco de conformidad HTTP/1.1
  • ✗
    Sin correr contra PostgreSQL o MySQL reales
  • ✗
    Sin prueba de carga sostenida con conexiones hostiles
  • ✗
    Sin log de acceso, métricas ni WebSocket
  • ✗
    Sesiones por proceso: no escala a varias instancias

Cuando todo eso se cumpla, el primer despliegue debería ir detrás de nginx o Caddy. El proxy absorbe TLS, slowloris, HTTP/2 y el log de acceso, que son justo los cinco puntos donde LuxCore es más joven.
