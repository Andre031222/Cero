01

En cinco minutos

Un controlador es una clase corriente. Lo que devuelve decide el formato: un objeto se serializa a JSON, un String sale como texto plano, null es un 204. Sin anotación de por medio.

Hola.javaJava
import lux.core.*;

@Route("/api/tareas")
public class TareaController {

    @Inject Tareas tareas;

    @Get
    public Object listar(@Query(value = "pagina", orElse = "1") int pagina) {
        return tareas.findPage(pagina, 20);
    }

    @Get("/{id}")
    public Object ver(@Path("id") long id) {
        return tareas.findById(id);
    }

    @Post
    public Object crear(@Body @Valid Tarea tarea) {
        return Result.created(tareas.insert(tarea));
    }
}

public static void main(String[] args) {
    Lux.run(8080, TareaController.class);
}

Eso es todo. Lux.run registra las rutas, levanta el servidor e imprime el puerto y el tiempo de arranque. No hay web.xml, ni contenedor, ni despliegue.

Con todo declarado

App.javaJava
Server servidor = Lux.app()
    .port(8080)
    .loadConfig()
    .views(Templates.fromClasspath("plantillas"))
    .fallback(StaticFiles.fromClasspath("estaticos", "/estaticos"))
    .service(new Catalogo())
    .authenticator(ctx -> sesiones.verificar(ctx.header("Authorization")))
    .use(Cors.allowing("https://app.pe"))
    .use(Csrf.enabled().exempt("/api/"))
    .use(RateLimit.perMinute(300))
    .controllers(TareaController.class, AdminController.class)
    .routes(r -> r.get("/salud", ctx -> "ok"))
    .start();

servidor.await();  // bloquea hasta que se apague

03

Rutas

@Route sobre la clase fija la base; los verbos sobre los métodos añaden el resto. Una regla, sin excepciones: un valor vacío mapea a la ruta base.

AnotaciónRuta resultanteNota
@Route("/api/tareas")/api/tareasBase de la clase
@Get/api/tareasValor vacío = la base
@Get("/{id}")/api/tareas/{id}Variable de ruta
@Get("/{id}/notas/{n}")…/{id}/notas/{n}Varias variables
@Get("/archivos/*")/api/tareas/archivos/*Comodín, solo al final
@Post @Put @Patch @Delete—Mismo criterio
  • Lo literal gana a lo variable. /tareas/nueva se resuelve antes que /tareas/{id}, sin importar el orden en que se declaren.
  • Sin @Route, la base sale del nombre de la clase: ReporteController → /reporte.
  • Las rutas duplicadas fallan al arrancar, no en la primera petición.
  • 405 con Allow. Si la ruta existe pero el verbo no, la respuesta enumera los verbos válidos.
  • HEAD se resuelve contra GET automáticamente, sin cuerpo.

Rutas sueltas, sin controlador

LambdasJava
.routes(r -> r
    .get("/salud", ctx -> "ok")
    .get("/version", ctx -> Map.of("version", "0.1.0"))
    .post("/eco", ctx -> ctx.bodyText()))

Inyección

Marca un servicio con @Service y se construye la primera vez que alguien lo pide. Los controladores lo reciben con @Inject, por campo o por constructor.

ServiciosJava
@Service
public class Catalogo {
    @Inject Repositorio repositorio;      // por campo
}

@Service
public class Facturas {
    private final Catalogo catalogo;
    @Inject Facturas(Catalogo catalogo) {   // por constructor
        this.catalogo = catalogo;
    }
}

// o a mano, útil para sustituir en pruebas
Lux.app().service(Reloj.class, () -> Instant.now())
  • Los servicios son singleton: una instancia por aplicación.
  • Se registran también por sus interfaces, así que puedes pedir el contrato.
  • Las dependencias circulares se detectan y el error nombra la cadena completa.

Validación

Las anotaciones van sobre los componentes de un record o los campos de una clase. @Valid junto a @Body valida antes de entrar al método.

AnotaciónCompruebaMensaje por defecto
@RequiredNo nulo, no vacío, no en blancoes obligatorio
@Length(min, max)Longitud del textodebe tener entre N y M caracteres
@Range(min, max)Rango numéricodebe estar entre N y M
@EmailFormato de correono es un correo válido
@Match("regex")Expresión regularno tiene el formato esperado
@OneOf({"a","b"})Valor de una listadebe ser uno de: a, b
@Satisfies(Regla.class)Tu propia reglael de la regla
Tarea.javaJava
public record Tarea(
        @Id long id,
        @Required @Length(min = 3, max = 120) String titulo,
        @OneOf({"baja", "media", "alta"}) String prioridad) {}

// una regla propia
public class Ruc implements Rule<String> {
    public boolean test(String v) { return v.length() == 11 && v.startsWith("20"); }
    public String message()    { return "no es un RUC válido"; }
}

Cuando algo falla, la respuesta es un 422 con el mapa de campos, sin escribirlo:

    "titulo": "debe tener entre 3 y 120 caracteres",
    "prioridad": "debe ser uno de: baja, media, alta"

08

Errores

Lanza HttpException con el estado que quieras, o registra un manejador con @OnError para una excepción de tu dominio.

Manejo de erroresJava
@Get("/{id}")
public Object ver(@Path("id") long id) {
    Tarea t = tareas.findById(id);
    if (t == null) throw new HttpException(404, "no existe la tarea " + id);
    return t;
}

@OnError(SaldoInsuficiente.class)
public Object saldo(SaldoInsuficiente fallo) {
    return Result.json(Map.of("motivo", fallo.getMessage())).status(422);
}
Las excepciones no controladas nunca filtran detalles

Cualquier excepción que no sea HttpException devuelve un 500 con el mensaje genérico «error interno». La traza va al ErrorReporter, no a la respuesta.

Seguridad

MiddlewareJava
.use(Cors.allowing("https://app.pe").credentials(true))
.use(Csrf.enabled().exempt("/api/"))
.use(RateLimit.perMinute(300).keyBy(ctx -> ctx.header("X-Cliente")))
.use((ctx, cadena) -> {                    // el tuyo propio
    long t0 = System.nanoTime();
    try { return cadena.proceed(ctx); }
    finally { registrar(ctx, System.nanoTime() - t0); }
})
PiezaQué cubre
CorsPreflight OPTIONS, credenciales, Vary: Origin. Con credenciales nunca responde *: devuelve el origen concreto.
CsrfToken en sesión, comparación en tiempo constante. Lee _csrf de la cabecera, del formulario o de la consulta. Exención por prefijo o con @CsrfExempt.
RateLimitVentana deslizante ponderada, cabeceras X-RateLimit-* y Retry-After, clave configurable.
Sanitizehtml() quita script, estilos, iframes y manejadores de evento; text() deja solo texto; filename() neutraliza rutas.
@RequireAuth401 si no hay principal.
@RequireRole("admin")401 sin autenticar, 403 con rol insuficiente.

Autenticación

AuthenticatorJava
.authenticator(ctx -> {
    String token = ctx.header("Authorization");
    if (token == null) return null;         // anónimo
    return Principal.of("andre", "admin");   // id + roles
})

El orden del pipeline es autenticar → middleware → autorizar → vincular → invocar → renderizar. Así el middleware ve el principal y a la vez puede envolver los 401 y 403 para registrarlos.

Lo que el servidor rechaza de oficio

Cabeceras plegadas, Content-Length duplicado, Content-Length junto a Transfer-Encoding, Host ausente o duplicado, caracteres de control en las cabeceras de respuesta, y salidas del directorio raíz en los archivos estáticos.

Bases de datos

lux-data habla JDBC y nada más. Sirve cualquier motor con driver JDBC — el driver lo pone tu aplicación, que es la única dependencia externa que LuxCore admite.

MotorEstadoNota
H2 2.2ProbadoEn memoria y en archivo. Motor de la app de ejemplo y sus 36 pruebas.
PostgreSQLSin verificarNada del código es específico de un motor, pero no se ha corrido.
MySQL / MariaDBSin verificarIgual.
SQL ServerSin verificarLIMIT/OFFSET tiene otra sintaxis; la paginación necesitará ajuste.
OracleSin verificarDevuelve columnas en mayúsculas, que ya está contemplado.
SQLiteSin verificarSin concurrencia de escritura; el pool debería ir a 1.
«Sin verificar» quiere decir sin verificar

Los tipos, las zonas horarias y la paginación cambian entre motores. La capa se prueba contra un driver propio que registra el SQL generado — eso cubre su responsabilidad, no las diferencias entre motores. Hasta correrla contra PostgreSQL y MySQL reales, «debería andar» es una hipótesis.

Dónde corre

No hay código nativo ni nada específico de una plataforma. Donde haya un JDK 21 o superior, corre igual.

SistemaEstadoNota
macOSProbadoIntel y Apple Silicon. Donde se desarrolló y donde corren las 642 pruebas.
LinuxSin verificarEs el destino previsto para producción, pero no se ha ejecutado allí.
WindowsSin verificarNada toca rutas ni permisos específicos del sistema.
ContenedoresSin verificarCualquier imagen con JRE 21. Sin contenedor de servlets, la imagen es el JRE más 223 KB.
Requisito real
Java 21 por los hilos virtuales: el servidor asigna uno por conexión, y sin ellos el modelo no se sostiene. Se desarrolló y midió con OpenJDK 25.
Sin código nativo
Ni JNI, ni bibliotecas del sistema, ni rutas absolutas. El JAR es el mismo en todas partes.

18

Estado

No usar en producción todavía

El servidor HTTP tiene días de vida. Una auditoría encontró una inyección CRLF a las pocas horas de escribirlo, y construir la primera aplicación real destapó otros cuatro fallos —entre ellos que la capa de datos devolvía todos los campos en null contra cualquier motor que use mayúsculas en los nombres de columna—. Todos están corregidos y cubiertos por pruebas. El punto es que aparecieron, y que ese proceso no ha terminado.

  • ✓
    642 pruebas en verde, cero dependencias verificadas
  • ✓
    Una aplicación completa corriendo de punta a punta: vistas, formularios, base de datos y API REST
  • ✓
    Endurecimiento explícito: request smuggling, path traversal, inyección de cabeceras, CSRF
  • ✓
    TLS, techo de conexiones, timeout de handler y apagado ordenado
  • ✗
    Sin fuzzing del parser ni banco de conformidad HTTP/1.1
  • ✗
    Sin correr contra PostgreSQL o MySQL reales
  • ✗
    Sin prueba de carga sostenida con conexiones hostiles
  • ✗
    Sin ejecutar nunca en Linux ni en Windows
  • ✗
    Sin log de acceso, métricas ni WebSocket
  • ✗
    Sesiones por proceso: no escala a varias instancias

Para qué sirve hoy

Para un proyecto interno, un prototipo o una herramienta de equipo, detrás de una red de confianza. No para algo que reciba tráfico de desconocidos.

Qué haría falta para cambiar eso

En orden, porque cada paso informa al siguiente: correr la capa de datos contra PostgreSQL y MySQL reales; migrar métricas y log de acceso, porque sin observabilidad no se opera nada; fuzzing del parser y conformidad HTTP/1.1; el banco de pruebas comparativo en hardware aislado; una prueba de carga larga con conexiones hostiles; y por último una aplicación pequeña y de bajo riesgo en producción, durante semanas, antes de mover nada importante.

Aun cumplido todo eso, el primer despliegue debería ir detrás de nginx o Caddy. El proxy absorbe TLS, slowloris, HTTP/2 y el log de acceso, que son justo los cinco puntos donde LuxCore es más joven.
