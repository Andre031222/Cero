@Route("/api/tareas")
public class TareaController {

    @Inject Tareas tareas;

    @Get
    public Object listar(@Query(value = "pagina", orElse = "1") int pagina) {
        return tareas.findPage(pagina, 20);
    }

    @Get("/{id}")
    public Object ver(@Path("id") long id) {
        Tarea t = tareas.findById(id);
        if (t == null) throw new HttpException(404, "no existe");
        return t;
    }

    @Post
    public Object crear(@Body @Valid Tarea tarea) {
        return Result.created(tareas.insert(tarea));
    }

    @Delete("/{id}")
    public Object borrar(@Path("id") long id) {
        return tareas.deleteById(id) == 0
             ? Result.status(404, "no existe")
             : Result.noContent();
    }
}
// The record is the entity, the validation and the mapping. There are no three classes.
@Table("tareas")
public record Tarea(
        @Id long id,
        @Required @Length(min = 3, max = 120) String titulo,
        @OneOf({"baja", "media", "alta"}) String prioridad,
        @Column("hecha") boolean completada) {}

@Service
public class Tareas extends Repository<Tarea, Long> {

    public Tareas() { super(Tarea.class); }

    public List<Tarea> pendientes() {
        return findBy("hecha = ?", false);
    }

    public void completar(long id) {
        Tx.run(() -> db().update("tareas",
                Row.of("hecha", true), "id = ?", id));
    }
}

Cero.run(8080, TareaController.class);

   .routes(r -> r.get("/salud", ctx -> "ok")
                 .get("/cero/metrics", metricas.endpoint()))
   .start()
   .await();
01

Why it exists

Cero grew out of JxMVC, an MVC framework that works and is in production — but that needs Tomcat to start. Dropping the container was not a whim: it accounted for 94 % of the boot time and 98 % of the deployed weight.

MetricJxMVC on TomcatCeroDifference
Boot698 ms106 ms6.6×

Runtime dependenciesJakarta EE 10none—

And you do not have to jump all at once: cero-adapter-servlet deploys a Cero application inside Tomcat, so the migration is reversible.

02

What it brings

Server

HTTP/1.1 with one virtual thread per connection. TLS, keep-alive, chunked, multipart, gzip, cookies, sessions and static files.

Routes

{var} templates, wildcards and one rule with no exceptions. Literal beats variable, and duplicate routes fail at startup, not in production.

Data

Plain JDBC with no ORM, plus pool, transactions and repositories. Verified against PostgreSQL 16, MySQL 8 and H2 with the same test suite.

Views

Compiled templates with inheritance, loops and includes. HTML escaping is the default behaviour, not an option you forget to switch on.

Security

CORS, CSRF, rate limiting, declarative validation, sanitising and security headers. Tested with hostile clients and malformed input.

Asynchronous

Background tasks on virtual threads, interval scheduling and five-field cron. A task that fails does not bring the scheduler down.

Integration

HTTP client with retries and server-sent events — which is how AI APIs stream, so consuming them is one line.

Identity

Sign in with Google, Microsoft or GitHub, with PKCE and signature verification of the id_token. Passwords with PBKDF2 and an embedded cost factor.

Observability

Per-route metrics with percentiles, in JSON or Prometheus format, and a combined or compact access log.
