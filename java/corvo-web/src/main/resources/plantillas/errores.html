Errores

Cómo responde el framework cuando algo va mal. Los dos enlaces provocan el error de verdad.

01

Pruébalos

Provocar un 403 Una excepción con estado, con su mensaje
Provocar un 500 Una excepción no controlada: el mensaje interno no sale
Provocar un 404 Una ruta que no está registrada
02

Qué devuelve

{
  "error": "Forbidden",
  "message": "Acceso denegado — recurso protegido",
  "path": "/error403"
}

En un 500 el campo message dice «error interno» y nada más: el mensaje real de la excepción se queda en el log del servidor, no viaja al cliente.
